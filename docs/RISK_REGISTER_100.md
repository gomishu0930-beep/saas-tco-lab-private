## 保存境界

- 非公開の成果報酬、確定率、クリック、成約、支払条件、ASP dashboard値、tracking ID、広告URL、
  個人情報は本書へ保存しない。元データが非公開の場合は`unknown`または状態だけを記録する。
- 公開safe-summaryは、承認済みHuman exportから個別queryを復元できない集計値だけを参照できる。
  現在参照するserversのknown需要は`28,220/月`であり、取得可能sessionsや売上を意味しない。
- 実績の発動記録は5 KPI等の公開可能な集計状態だけを残す。外部dashboardの原値、URL全文、
  message ID、識別子は保存しない。
- 税務・法務・ASP規約は一律の金額基準を推測せず、適用条件が発生した時点で公式情報または
  専門家へ確認する。

## ループの閉じ方(この登録簿の設計思想)

「懸念 → 施策 → その施策の懸念 → 施策…」は無限再帰であり、そのままでは閉じない。
本登録簿は制御ループとして有限に閉じる。各行が次の4要素を持つ。

1. **懸念** — 何が起きると困るか
2. **施策** — 何をするか
3. **検知** — 施策が効かなかったことを、いつ・何の数値で気づくか(= 施策の懸念点への回答)
4. **代替** — 検知したら何に切り替えるか(= 二次施策)

三次以降は個別に展開しない。すべての代替が尽きた場合の終端状態を
`docs/PRODUCTION_ROADMAP.md`の撤退ライン(2026-12-31判定)に一本化する。
終端状態があることで、このループは有限で閉じる。

## Tier定義

- **T1 = 実装で潰す**(Codexが今回まとめて実装。記事作業の時間を消費しない)
- **T2 = 運用ルールで潰す**(checklist/runbookへ落とし、記事作業の中で自然に実行)
- **T3 = 監視のみ**(閾値を決め、超えた時だけ発動。平時はコストゼロ)

Tierは事後に上げてよいが、T1を増やすときは記事本数の目標を先に確認する。
実装が記事を止めるなら、その実装は延期する。
