# P10 Work Packet: Pre-publication release assurance

## Objective

Close every external-credential-free item in the Phase 5 public-release gate. Produce a threat model,
deterministic lockfile-derived SBOM, synthetic-local accessibility/mobile/SEO assurance, and one typed
fail-closed release-assurance decision. Do not deploy, publish, fetch vendor sources, create accounts, or
introduce real prices, Affiliate URLs, secrets, domains, or approvals.

## Role and ownership

- Contract/Storage owns `scripts/export_sbom.py`, `tests/test_sbom.py`, `docs/SBOM_RUNBOOK.md`, and
  generated `artifacts/release-assurance/sbom.cdx.json`.
- Governance owns `docs/THREAT_MODEL.md`.
- TCO/QA owns `site/tests/prepublication-assurance.test.mjs`, necessary synthetic-local UI/CSS metadata
  corrections, and the matching `site/package.json` test command change.
- Integration/Release owns `src/saas_preflight/release_assurance.py`, Python tests/schema integration,
  release-assurance runbook/report, workflow integration, and final verification.

## Contract/Storage acceptance

1. Use Python standard library only. Parse root `uv.lock` and `site/package-lock.json`; never query a registry.
2. Emit deterministic CycloneDX JSON with fixed spec/version, root applications, all resolved components,
   package URLs, available lockfile hashes, declared npm license data, dependency edges, and lockfile SHA-256
   evidence. No current timestamp, absolute path, host/user data, URL credential, or unordered collection.
3. Reject missing lockfiles, duplicate component identities, malformed/insecure package sources, missing
   versions, malformed integrity values, and dependencies that cannot be resolved to a component.
4. Write through an exclusive create boundary by default; an explicit `--check` compares generated bytes
   without overwriting. Output is newline-terminated canonical JSON.
5. Tests cover determinism, permutation resistance where applicable, both ecosystems, tampered/missing lock
   data, path independence, URL credential rejection, and `--check` drift detection.

## Governance acceptance

1. Model assets, trust boundaries, entry points, threat actors, and abuse cases for rights intake, safe-summary
   ingestion, append-only storage, TCO/gold set, attestations/keys, serving lease, Worker/static assets,
   Affiliate redirects, analytics, CI/supply chain, operator workstation, backup/retention, and SEO abuse.
2. For every material threat state prevention, detection, containment/kill switch, recovery, residual risk,
   owner, and the Human-only decision boundary.
3. Include credential rotation/revocation, lease/key compromise, source-policy expiry, dependency compromise,
   XSS/open redirect/SSRF, raw/PII leakage, false price/ranking, stale index, crawler exposure, and denial of
   service. Do not claim controls that are not implemented.
4. Separate implemented local controls, required production controls, accepted residual risks, and launch
   blockers. The current public decision remains STOP.

## TCO/QA acceptance

1. Reuse the existing synthetic-local build; no new dependency or browser download.
2. Test all five rendered routes for one `main`, unique non-empty `h1`, Japanese language, viewport metadata,
   noindex metadata, title/description, labelled navigation, skip-link target, valid internal links, disabled
   CTA, disclosure proximity, table caption/headers, and no accidental canonical/JSON-LD/public origin.
3. Add static mobile/reflow guard tests for the 900px and 620px breakpoints, no page-level fixed minimum
   width, intentional table scrolling, visible keyboard focus, and reduced-motion behavior.
4. Production actual-HTTP tests must remain fail-closed for pages and static assets. SEO structured data and
   canonical remain deliberately absent until a real approved domain and real source-backed data exist.
5. Corrections must preserve the synthetic-only/noindex boundary and may not add active external links.

## Integration/Release acceptance

1. Create strict typed contracts for assurance evidence, check status, release decision, expiry, artifact and
   config binding. Caller-supplied aggregate booleans or unchecked counts may not produce GO.
2. Recompute each required check from typed evidence at evaluation time. Required checks: Python tests,
   Web local/production tests, schema determinism, lock integrity, SBOM determinism/currentness, secret scan,
   dependency audit, threat-model review, accessibility, mobile, robots/canonical/structured-data policy,
   rollback/fault tests, rights, Affiliate, demand/cohort, 30-day operations, and Human approval.
3. Distinguish `local_assurance_ready` from `public_release_ready`. Local evidence can pass while public release
   remains STOP because external business/Human gates are missing.
4. Bind the report to exact evidence IDs/hashes, release/manifest/artifact, policy version, evaluated time,
   expiry, and a canonical report hash. Future, expired, duplicate, unknown, conflicting, wrong-scope,
   copied/tampered, or incomplete evidence must fail closed.
5. Export deterministic schemas and provide a synthetic report plus a current-real-state STOP report without
   inventing production facts.

## Verification

Run focused tests, then full Python tests, deterministic schema and SBOM re-export, lock/compile checks,
Gitleaks, local and actual-HTTP production Web tests, ESLint, npm audit, and workflow verification. TCO/QA and
Governance must perform independent adversarial review after integration; P10 completes only with no release
blocker in the local assurance boundary. Public release must remain STOP.
